How to read this page

Action needed

A call that was correct before is wrong now, and we can say so with certainty: the endpoint is gone, authentication changed, the URL's path variables changed, or the request body switched format. Change your code for these.

Worth checking

Something moved that may or may not reach you — a parameter, a field in a request or response example, a header. We can see it changed but not whether your calls depend on it. One comparison against your integration settles it.

New

Only adds: a new endpoint, a new optional parameter, an extra field in a response. Nothing to change. Pick it up when you're ready.

Documentation

How the documentation reads or is organised — wording, a section, a name, which examples are shown. The API itself is unchanged. Nothing to do.

Where this comes from

We compare the full published API surface at dev.wxrks.com against the previous known state and record what moved. That covers every documented endpoint along with its parameters, request body and response shape. The date on each entry is the date we detected the change.

Every route listed on this page links to its own section in the documentation, so you can go from a line here to the endpoint's full reference in one click.

Entries marked detected automatically are written by that comparison rather than by a person. They state what moved and nothing more — we don't guess at whether a change reaches your integration, because from here we can't know. If one affects you and the detail isn't enough, say so and we'll add it.

One caveat worth being straight about: this tracks the API as documented. An update that ships without the documentation changing won't appear here, so if you come across one, tell us. That's a gap we want to know about.
